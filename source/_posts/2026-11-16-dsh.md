## 一、版本概述

### 1.1 产品定位变化

DeepSeek Harness（简称 DSH）v0.2 预览版是产品从**面向开发者的命令行 Agent 框架**，转向普通用户可开箱即用的桌面端产品的核心版本。官方提供原生 Windows 64 位安装包，下载安装后按引导即可直接使用，无需手动搭建 Node.js 运行环境，无需通过命令行启动服务。

相比 v0.1 系列，其核心形态变化为：

- 从纯命令行操作，升级为图形化桌面应用
- 基础办公、开发能力内置，不再是零功能的纯框架
- 插件体系可视化管理，降低普通用户上手门槛

### 1.2 0.2.1-rc.5 → 0.2.2-rc.1 核心更新

#### 新增核心能力

1. **Computer Use 双版本切换**：新增新版计算机控制套件，与旧版支持一键切换，macOS 14+ 启用 PTC 模式后自动适配
2. **OAR 子代理体系内置**：官方新增子代理套件，支持调用本地 Claude Code、Codex CLI 作为子代理，配套可视化权限配置页
3. **会话全文搜索**：内置 Session Search 能力，支持快速检索历史会话内容
4. **插件管理增强**：支持第三方插件一键更新、热重载状态提示、插件快速创建入口

#### 体验与性能优化

- AGENTS.md 规则加载优化：全局与项目规则分开计算预算，总上限提升至原 2 倍，避免长规则被截断
- 上下文缓存复用：系统提示不变时，切换模型自动复用前缀缓存，降低重复 token 消耗
- 模型切换更稳健：切换小窗口模型前自动压缩历史，压缩失败则终止切换并保留原内容
- 交互响应优化：手动打断时立即返回当前结果，修复切换会话后输入草稿丢失的问题
- 凭据联动优化：缺少对应 API 凭据时，自动隐藏相关工具，避免展示不可用功能

#### 底层与兼容性变化

- 内核升级：底层 Cordis 运行时升级至 4.0.6 系列，插件加载与热重载稳定性提升
- 破坏性变更：部分底层接口契约调整，依赖相关接口的第三方插件需适配升级
- 运行要求：Node.js 最低版本要求提升至 `>=24.9.0`（桌面端内置对应运行时，用户无需手动配置）

## 二、原生核心能力

v0.2 桌面端已内置大量基础能力，日常场景无需额外安装插件。

### 2.1 开箱即用的基础功能

- **文件处理**：文件读写、格式转换，支持 Excel/CSV/TSV 等数据文件直接预览
- **开发能力**：代码编写、Bug 修复、代码仓库浏览、原生 Shell 终端调用
- **信息检索**：内置 DeepSeek 官方网页搜索能力
- **会话管理**：支持会话置顶、归档、搜索恢复，长任务支持后台运行
- **子代理能力**：原生支持 Subagent 递归调用，可拆分独立子任务

### 2.2 AGENTS.md 持久化指令机制

DSH 原生支持的项目级规则体系，无需任何插件即可使用：

- **作用**：将固定、长期的规则沉淀到文件中，新会话自动加载，无需每次重复说明要求
- **分层逻辑**：采用从全局到局部的递归加载机制，内层规则优先级更高
    - 全局层：`~/.dsh/AGENTS.md`，对本机所有项目生效
    - 项目层：项目根目录下的 `AGENTS.md`，仅对当前项目生效
    - 目录层：子目录下的 `AGENTS.md`，仅对该目录及子目录生效
- **核心特性**：文件修改后自动感知生效，无需重启会话；总内容有 64KiB 预算限制，超出时优先保留内层规则
- **适用场景**：编码规范、输出格式、工作流程、禁忌事项；不适合一次性临时任务指令

### 2.3 原生插件管理系统

v0.2 新增可视化插件管理页面，支持：

- 图形化查看所有已安装插件，支持启用/禁用、卸载操作
- 输入插件标识即可完成安装，无需记忆命令行指令
- 插件详情页可查看版本号、官方仓库地址、运行配置项

## 三、插件安装与管理指南

### 3.1 支持的插件标识格式

桌面端「+ 添加插件」输入框与命令行支持三类标识：

1. **npm 包名（日常首选）** 格式：`包名` 或 `包名@版本号`，例如 `dsh-memoir@0.9.5` 特点：安装官方发布的稳定版本，版本固定可追溯，安全性最高
2. **GitHub 仓库地址** 格式：`github:所有者/仓库名`，例如 `github:Qinling-Melon-Farmers/dsh-memoir` 特点：直接拉取源码安装，可使用最新开发功能，适合有源码核验需求的用户
3. **本地路径** 格式：`link:本地绝对路径` 特点：仅用于本地开发调试自定义插件，普通用户基本不会用到

### 3.2 三种安装方式

#### 方式 1：桌面端图形界面安装（最推荐）

1. 打开 DSH 桌面端，点击侧边栏进入「插件」管理页面
2. 点击右上角「+ 添加插件」按钮
3. 在输入框中填写完整插件标识（建议指定版本号），确认安装
4. 安装完成后，**彻底重启 DSH 桌面端进程**生效（仅刷新页面无效）

#### 方式 2：命令行安装（功能最全面）

在系统终端或 DSH 内置终端执行：

```
# 桌面端对应 desktop profile
dsh plugin --profile desktop add 插件包名@版本号

# 示例：安装 dsh-memoir 0.9.5 版本
dsh plugin --profile desktop add dsh-memoir@0.9.5
```

> 注意：Web 端与桌面端使用独立的 profile，插件需分别安装；同一 DSH_HOME 目录下，记忆、设置等用户数据可共享。

#### 方式 3：添加索引源或安装插件市场

索引源示例：
```
https://cdn.dsh.so/market/index.json
```

**添加索引源**

1. 打开 **插件 → 实验性插件 → 自定义插件索引** 已开启。
2. 在 **已安装** 旁边进入 **发现**。
3. 点击 **添加索引源**。
4. 粘贴上面的完整地址，注意必须包含最后的 `/index.json`。
5. 保存后，在市场菜单里应该能看到 **DSH.SO 安装验证与安全审计插件市场**。
6. 搜索插件，点开卡片，核对来源、版本和兼容的 DSH 版本，再安装。

>注意：DSH 官方**没有内置任何索引源**，也没有“官方认证市场”，在「发现」里添加的都是第三方市场。索引源只负责“列出插件”，不代表插件一定安全。插件安装后会读取本地文件、执行命令，安装前要看清楚来源。

**安装插件市场**

 **dsh-market**：一个可以安装在 DSH 内的可视化插件市场，收录了**数千款插件**。在桌面端，你可以在 **“插件 → 添加插件”** 中搜索 `dshmarket` 来安装这个市场本身，之后就能通过它浏览和安装其他插件了。

### 3.3 查看已安装插件的包名

1. **图形界面查看**：进入插件管理页，点击目标插件进入详情页，即可看到完整 npm 包名与版本号
2. **命令行精准查询**：

```
dsh plugin --profile desktop list
```

### 3.4 插件升级与卸载

#### 升级方法

- **无需先卸载旧版本**，直接安装目标新版本即可完成覆盖升级
- 升级仅替换插件程序本身，所有用户数据、配置、记忆文件都会完整保留
- 升级后需重启 DSH 进程生效；当前会话的冻结快照会在下一个新建会话中更新

#### 卸载说明

- 卸载插件仅移除插件功能，不会删除对应的用户数据（如记忆文件、配置文件）
- 重新安装同版本插件后，原有数据可自动恢复

### 3.5 安全安装渠道与避坑建议

安全优先级从高到低：官方内置插件 > npm 官方源成熟插件 > 知名 GitHub 开源仓库 > 私人零散分享

- **npm 官方源**：有平台基础安全扫描、包名唯一保护，版本发布后不可篡改，是日常使用的最优选择
- **GitHub 仓库**：源码完全透明可审计，但主分支代码可能包含未测试的开发功能，建议固定到具体 tag 版本
- **高风险渠道**：聊天群、网盘流传的离线压缩包、一键安装脚本，严禁随意安装

## 四、精选实用插件推荐

### 4.1 记忆类：dsh-memoir（必装）

- **作者**：Qinling-Melon-Farmers
- **npm 包名**：`dsh-memoir`
- **GitHub 仓库**：[https://github.com/Qinling-Melon-Farmers/dsh-memoir](https://github.com/Qinling-Melon-Farmers/dsh-memoir)
- **安装命令**：

```
dsh plugin --profile desktop add dsh-memoir
```

dsh-memoir 是一款面向 DeepSeek Harness 的**本地优先、跨会话项目记忆插件**，核心解决 DSH 原生不具备跨会话上下文继承、新会话无法复用过往项目经验的问题。它全程本地运行，不上传任何数据到云端，也不依赖外部大模型、向量数据库或第三方服务。

**推荐配置值**（其他默认即可）

|配置项|推荐值|调整说明|
|---|---|---|
|autoDistillEvery|3|每 3 个有效工作回合触发一次蒸馏，避免频繁打断任务|
|autoDistillCooldownMin|15|两次成功蒸馏最短间隔 15 分钟，集中沉淀更高效|
|autoDistillMinTools|2|至少 2 次工具调用才触发，过滤纯闲聊的无效回合|
|hotMemoryTokens|800|常规 Hot Memory 预算，平衡记忆量与 token 占用|
|readDefaultLimit|6|默认召回 6 条结果，避免信息冗余干扰 Agent|

### 4.2 余额与 Token 用量类：balance-dsh

- **作者**：Rannist
- **npm 包名**：`balance-dsh`
- **GitHub 仓库**：[https://github.com/Rannist/balance-dsh](https://github.com/Rannist/balance-dsh)
- **安装命令**：

```
dsh plugin --profile desktop add balance-dsh
```

**核心功能**：在侧边栏直接显示**DeepSeek 账户余额**和**当前会话的 Token/金额消耗**。点击余额可展开详细弹窗，查看 Token 构成、缓存命中率、按模型（Flash/Pro）和高峰/空闲时段的拆分，以及 90 天使用热力图。
    
**亮点**：对 **DeepSeek 官方账户**的支持最直接，计费估算按官方价表进行，并自动同步节假日安排来区分高峰/空闲时段。

### 4.3 上下文优化类：

#### （1）dsh-context-budget 审计版

- **作者**：bushizhanghan
- **npm 包名**：`@bushizhanghan/dsh-context-budget`
- **GitHub 仓库**：[https://github.com/bushizhanghan/dsh-context-budget](https://github.com/bushizhanghan/dsh-context-budget)
- **安装命令**：

```
dsh plugin --profile desktop add @bushizhanghan/dsh-context-budget
```

这是一款**只读**的审计插件，不修改任何行为，也不调用 LLM。它专门用来分析每一轮对话中，有多少 token 被**逐字节重复注入**（如 AGENTS.md、技能目录、工具 schema），并给出浪费占比和排名，帮助你定位“固定开销”的来源。

- **核心工具**：
    - `ctx_budget`：审计单会话上下文构成，统计重复注入的无效 token 浪费
    - `ctx_budget_sweep`：扫描所有历史会话，按浪费量从高到低排序
    - `ctx_budget_skills`：分析技能目录开销，标记从未调用的冗余技能
    - `ctx_budget_tools`：分析工具 schema 膨胀，定位最占 token 的插件

- **使用注意**：
    - 需在安装插件后**新建的会话**中调用，旧会话工具列表不会更新
    - 纯本地运算，不调用大模型，只读会话日志，无任何副作用
    - 指令中明确限定输出格式，可大幅降低响应耗时与 token 消耗

#### （2）dsh-ctx-trim（压缩上下文）

- **作者**：AlexSh1ne
- **npm 包名**：`dsh-ctx-trim`
- **GitHub 仓库**：[https://github.com/AlexSh1ne/dsh-ctx-trim](https://github.com/AlexSh1ne/dsh-ctx-trim)
- **安装命令**：

  ```
  dsh plugin --profile desktop add dsh-ctx-trim
  ```

`dsh-ctx-trim` 是一款**手动、本地、不调用模型**的压缩插件， 安装后刷新页面，**会话标题右边会多出一个「上下文」按钮**，点击后可以选择 **“正常压缩”**（保留最近 **30%** 的 Token）或 **“深度压缩”**（保留最近 **10%** 的 Token），整个过程在本地完成，**不产生模型调用费用**。

## 五、实用使用技巧

### 5.1 减少 Token 用量的有效方法

1. **精简系统规则**：AGENTS.md 分层书写，全局只放核心通用要求，项目专属规则放项目目录；用短句条目化，删除冗余修饰
2. **优化记忆配置**：收紧 Hot Memory 预算，降低自动蒸馏频率，定期归档过时、失效的旧记忆
3. **拆分长任务**：大型任务拆分为多个会话处理，跨会话依赖记忆插件延续上下文，避免单会话历史无限膨胀
4. **约束输出格式**：固定输出模板，要求直接给出结论，禁止冗余客套话、重复确认和过度解释
5. **善用前缀缓存**：系统提示、记忆前缀尽量保持稳定，减少频繁修改，充分利用缓存降低重复消耗
6. **按需匹配模型**：简单任务用轻量模型，复杂任务再用高配模型，避免大材小用

### 5.2 跨 AI 工具协作一致性方案

1. 建立**单一主版本**的个人协作规范文档，包含指令、风格、格式、禁忌等内容
2. 同步到各工具的持久化入口：DSH 的全局 AGENTS.md、豆包记忆、其他产品的自定义指令
3. 统一输出格式、文件命名、工作流程，确保不同工具产出可直接归档复用
4. 本地核心数据定期备份，支持跨设备、跨环境迁移与恢复

### 5.3 数据备份建议

- Windows 系统默认 DSH 数据目录：`C:\Users\你的用户名\.dsh`
- 核心需备份内容：会话日志、全局配置、插件记忆文件、全局 AGENTS.md
- 大版本升级前，建议完整备份该目录，避免存储格式调整导致数据异常

## 六、常见问题排查

### 6.1 新装插件在旧会话里找不到对应工具？

- **原因**：DSH 每个会话的工具列表在创建时就已快照固定，后续新安装的插件不会动态注入已存在的旧会话
- **解决方法**：安装插件并重启 DSH 后，新建一个会话即可正常使用新工具；旧会话的历史日志仍可被审计类插件正常读取

### 6.2 升级插件需要先卸载旧版本吗？

升级到 v0.2.2-rc.1后，支持第三方插件一键更新。直接安装目标新版本即可覆盖升级，所有用户数据、配置、记忆都会完整保留，不会丢失。

### 6.3 升级系统 Node.js 会影响 DSH 桌面端吗？

不会。DSH 桌面端内置了独立的 Node.js 运行时，不依赖系统安装的 Node 环境。系统 Node 的升级、降级、卸载，都不会影响 DSH 桌面端的正常运行。 仅 npm 全局安装的命令行版 DSH，才会使用系统 Node 环境。

### 6.4 功能重复的插件会冲突吗？

- 单纯业务功能相似、工具 ID 不同的插件，不会引发程序崩溃，但可能增加 Agent 的选择成本
- 三类场景一定会出现冲突：
    1. 两个插件注册了完全相同的工具 ID/服务名，后加载的会覆盖先加载的
    2. 同时修改同一个 UI 区域，争抢界面挂载点，导致界面错乱
    3. 核心依赖版本不一致，引发调用报错
- **规避方法**：同类功能优先保留官方原生插件；用不同 profile 隔离不同场景的插件组合

### 6.5 DSH 桌面端突然打不开了，怎么办？

先彻底退出 DSH，然后打开资源管理器，在地址栏里输入`\%AppData%\@deepseek-ai\dsh-desktop\Network`回车，删除 Cookies 和 Cookies-journal 这两个文件。

DSH 启动时，本地服务端口是**随机**的（`--port 0`），而登录 Cookie 的名称是基于“地址+端口”生成的。端口一变，Cookie 名就变，浏览器会把它识别为一个**全新的 Cookie**，而不是去覆盖旧的。这些 `dsh-auth-*` Cookie 的有效期默认是 **30 天**，在过期前，它们都会一直堆在数据库里。而 Chromium 对于“过期”的 Cookie 通常只是**不再发送**，并不保证立刻从数据库中物理删除。浏览器向 `127.0.0.1` 发请求时，会带上**所有**尚未过期的 `dsh-auth-*` Cookie。每个 Cookie 约 227 字节，当它们累积到约 **70 条**时，总大小就会超过 Node.js 默认的 **16KB 请求头上限**。此时服务器会直接返回 `431 Request Header Fields Too Large`，DSH 的界面就永久卡在认证失败或干脆打不开了。删除 `Cookies` 和 `Cookies-journal`后，DSH 在下次启动时发现 `Cookies` 文件不存在，就会**自动创建一个全新的、空的数据库**，请求头瞬间恢复清爽，应用也就正常了。
